# PawSpot: продукт

Статус: Phase 0, проект MVP. Дата: 2026-10-03.

## Цель и аудитория

PawSpot сохраняет встречи с городскими котами и собаками и собирает историю каждого животного. Первый пилот — небольшая группа друзей в Тбилиси, Грузия. Это коллекция и исследование города, а не система отслеживания текущего местонахождения животных.

- Animal — персонаж, общий для пользователей.
- Encounter — контент: одна встреча, один автор, одно фото.
- Map — исследование приблизительных областей встреч.
- Collection — животные, которых пользователь встретил сам.

Успешный основной сценарий занимает примерно 15–30 секунд при нормальной сети. Это проверяемая UX-гипотеза, не гарантия времени загрузки фотографии. На пилоте измеряем время от нажатия Add до подтверждения сохранения, отдельно отмечая ожидание сети, медиану и медленные прохождения.

## Быстрое добавление

1. «Добавить встречу» в боте либо Add в Mini App.
2. Фото и выбор кот/собака.
3. Геолокация с согласия пользователя, точка на карте в Mini App либо «Пропустить».
4. До пяти кандидатов: фотографии и краткие карточки. «Новое животное» всегда доступно.
5. Выбор существующего Animal или нового; имя нового необязательно.
6. Короткая заметка необязательна. Отдельная кнопка «Сохранить без заметки».
7. Backend атомарно сохраняет Encounter и при необходимости Animal.
8. Карточка результата и стабильная ссылка. Повторное нажатие не создаёт вторую встречу.

Бот работает в личном чате. Обычный путь не требует открытия Mini App. Перезапуск бота не уничтожает незавершённый черновик. Один активный черновик на пользователя для обоих интерфейсов; при конкурирующем редактировании интерфейс перечитывает актуальное состояние. «Отмена» удаляет черновик, не опубликованную встречу.

Если фото загружено без координат, встреча всё равно сохраняется и попадает в коллекцию и ленту, но не на карту. Nearby matching пропускается; можно выбрать Animal из своей коллекции или из уже открытого профиля. Отсутствие кандидатов не доказывает, что животное новое.

Город — контекст, а не обязательный шаг каждого добавления. В пилоте интерфейс предлагает Тбилиси. При координатах далеко от выбранного города backend не присваивает его автоматически: сохраняет неизвестный город или предлагает выбор. Без координат допустим выбранный пользователем город. Точный адрес не требуется.

## Экраны

| Экран | Содержимое и поведение |
| --- | --- |
| Map | Области последних известных встреч; кот/собака; карточка с фото, именем, числом встреч и датой последней встречи; переход к Animal |
| Feed | Последние опубликованные встречи: фото, животное, приблизительная область, время, заметка, автор, реакции |
| Add | Тот же workflow, что у бота; незавершённое добавление можно продолжить |
| Profile | Уникальные животные, коты, собаки, встречи, области, полученные реакции; коллекция с пагинацией |
| Animal | Главное фото, имя либо «Без имени», вид, город, область, встречи, фото, уникальные авторы, реакции, первая/последняя встреча, первоначальный создатель; timeline |

Map использует последнюю встречу **с геолокацией**. Если более новая встреча без точки, дата географического наблюдения показывается отдельно. На карте нет обещания «животное сейчас здесь».

MVP не получает официальные границы районов. «Область» означает устойчивую ячейку приблизительного местоположения. В статистике считаем уникальные ячейки, подписываем «Области встреч», не «Районы Тбилиси». Поиск адресов и reverse geocoding не нужны для первого пилота.

## Правила

- Встреча принадлежит одному автору и одному Animal. Нельзя создавать Animal без первой встречи.
- Для MVP ровно одно фото на Encounter. Количество фотографий равно количеству видимых встреч; главное фото выбирается из них.
- Имя не уникально и не используется для идентификации. У Animal нет владельца в смысле права остальных запретить встречи.
- Время наблюдения по умолчанию — время добавления. Можно указать прошлое время; будущее за пределами допустимой погрешности часов отклоняется.
- Один пользователь может поставить по одной реакции каждого вида: like, funny, cute. Самореакции в пилоте запрещены; они не увеличивают статистику автора.
- Collection вычисляется по уникальным Animal в собственных видимых Encounter; отдельного ручного «добавить в коллекцию» нет.
- Полученные реакции — реакции на встречи пользователя, а не на всех животных его коллекции.
- После merge статистика уникальных животных пересчитывается; фотографии и встречи сохраняются.
- Автор может удалить свою встречу. Она исчезает из выдач и счётчиков; удаление фото и приватных данных выполняется по операционной процедуре. Полноценный редактор и модераторский UI вне MVP.
- Первая встреча по observed_at и первоначальный создатель Animal — разные факты: задним числом добавленная встреча не меняет создателя.

## Приватность и доступ

Решение владельца: закрытый пилот по allowlist Telegram ID. Share links стабильны, но доступны только участникам пилота. Анонимный публичный доступ по ссылке может появиться позднее как отдельное продуктовое решение. Слово «публичные координаты» обозначает безопасное представление для других авторизованных пользователей, а не анонимный доступ из интернета. Политика MVP запрещает возвращать точные координаты через обычный API, включая автора; позже её можно пересмотреть отдельно.

Точная точка никогда не показывается в обычных API, даже автору. Фотографии перекодируются без EXIF/GPS. Пользователь видит подсказку не публиковать точные адреса, контакты, лица и данные на ошейниках. Система не гарантирует анонимность: место может быть узнано по изображению или заметке. Скрытие чувствительного контента оператором необходимо до пилота; сложная moderation platform не нужна.

Тексты отображаются как plain text. Для публичного имени автора используется display_name; telegram_id и username не возвращаются в карточках. Не строим публичные страницы пользователей или историю их перемещений.

## В MVP не входит

AI identification, распознавание пород, приюты, усыновление, ветеринария, донаты, сообщения и чат, валюта, XP, уровни, задания, сложные achievements, native apps, полноценная социальная сеть и moderation platform.

Будущие embeddings, aliases, notifications, reports, lost/found и лидерборды не получают таблиц, очередей или интерфейсов заранее. Для AI достаточно сохранить независимый matching use case и нормализованные фото.

## Неоднозначности требований и решения

| Вопрос | Решение Phase 0 |
| --- | --- |
| 10 шагов бота против 15–30 секунд | Необязательные поля пропускаются кнопкой; нет обязательного подтверждения каждой мелочи; проверяем на людях |
| Геолокация optional, карта обязательна | Встреча без точки не попадает на карту; остальные возможности сохраняются |
| Случайное смещение около 200 м | Фиксированная сетка областей; повторные публикации не создают независимых шумовых точек |
| Nearby в поздней Phase 7 | Переносим matching до encounter flow; визуальная карта остаётся позднее |
| Privacy/auth в конце проекта | Закладываем до первого реального фото; поздняя фаза усиливает, а не впервые включает защиту |
| Несколько городов и Animal.city_id | Encounter хранит город наблюдения отдельно; Animal.city_id — исходный город, не ограничение перемещения |
| Несколько фото в профиле | Несколько Encounter; альбом в одной встрече пока не нужен |
| Неизвестный район | Приблизительная область вместо придуманного административного района |
| Открытый sharing против теста среди друзей | Владелец выбрал закрытый пилот; открытие интернета — отдельное продуктовое решение |
